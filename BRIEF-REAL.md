## Product: Creality Ender-3 3D printer (original Ender-3)
Why: Creality published the full CAD + official BOM with real Creality part codes under GPL-3.0 at https://github.com/Creality3DPrinting/Ender-3 ; Ender-3 replacement parts are sold by many real retailers whose stores expose keyless public product JSON.

### Model (already converted, in repo)
`public/models/ender3.glb` (1.6 MB, ~330k tris, EXT_meshopt_compression + KHR_mesh_quantization → use MeshoptDecoder). Converted by me from `Ender-3 Mechanical/STP/Ender3.STEP` with occt-import-js + gltf-transform (scripts/step-to-occt.cjs, scripts/step-to-glb.mjs; meshes simplified). Units: meters. Structure: scene → node "Ender-3" → 225 occurrence nodes named "<STEP name>#<n>" with `extras.stepName` = the STEP part name (e.g. "Hot bed", "42-34 motor", "V Wheel Component", "M5X30 Pan Head Screw", "Sprinkler assembly"); each has child mesh nodes. NO NORMALS and ONE gray material: at load, for each mesh compute creased normals (`toCreasedNormals` from three/examples/jsm/utils/BufferGeometryUtils.js, ~30°) and assign realistic materials per part group (aluminum extrusion silver, black anodized/steel for brackets & motors, PEI/black bed, red-ish? no—keep Ender-3 look: black sheet metal, silver extrusions, blue PCB hidden in enclosure, brass nozzle, white/black belts, black POM wheels). Orientation: verify up axis visually (Y-up expected; fix rotation if printer lies on its side) and center on ground.

## Live data — serverless (Vercel Node functions in /api, ESM, zero deps, global fetch)
`/api/offers?part=<id>`: for the part's live config, query these REAL retailers' public Shopify endpoints in parallel (timeout ~6 s each, Promise.allSettled):
  printedsolid.com, store.micro-swiss.com, e3d-online.com, www.fabreeko.com, west3d.com, www.3dprintingcanada.com, www.digitmakers.ca
  - search: `https://<host>/search/suggest.json?q=<query>&resources[type]=product&resources[limit]=6`
  - filter titles by mustMatch/excludes, keep top 2 per store, then fetch `https://<host>/products/<handle>.js` for vendor, title, variants (sku, barcode, price in cents, available), url, image.
  - currency per store: fetch `https://<host>/cart.js` → `.currency` (cache in module scope). Never assume USD.
  - Return JSON: { part, fetchedAt ISO, sources:[{host, ok, ms, error?}], listings:[{store, host, title, vendor, url (absolute product url on that store), image, price, currency, available, sku, barcode, gtinValid (GS1 mod-10 check), fetchedAt}] } sorted by available then price. Set `Cache-Control: s-maxage=1800, stale-while-revalidate=86400`. Send a descriptive User-Agent ("gs1-3d-catalog-poc (+https://gs1-3d-catalog-poc.vercel.app)").
`/api/gtin?gtin=<digits>`: keyless UPCitemdb trial lookup `https://api.upcitemdb.com/prod/trial/lookup?upc=<gtin>` (100 req/day per IP; often EXCEED_LIMIT) → return its item facts (title, brand, model, offers count) or {error:'rate_limited'} gracefully; s-maxage=86400.
Put shared logic in api/_lib/*.js (underscore so Vercel doesn't route it). Also mount the same handlers in Vite dev+preview via a small plugin (configureServer/configurePreviewServer middleware) so local verify hits the real live endpoints.
